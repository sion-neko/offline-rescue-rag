# 0006 答えは「AI が選んだ原文の行」と「いちばん近い資料の原文」

- 状態：採用（「いちばん近い資料」は 0013 で QA になった）
- 日付：2026-11-16、2026-11-17

## 背景
- LLM に自由に要約させると、意味を変えたり資料にないことを書いたりした（0005）
- 要約の各行と原文の近さを点数にして、作り話を見分けようとしたが、できなかった。真逆の文（距離を最小限に）が本物の文より高い点数になった（`scripts/eval-cite.mjs`）
- 遭難した人は、書いてあることをそのまま実行する。間違いが混ざりうるものを答えの本体にしたくない

## 決定
1. LLM に「資料の文をそのまま書き写して、質問に合う文を大事な順に選ぶ」よう頼む（`docs/prompts/v3-copy.json`）
2. LLM が書いた行のうち、原文の行と近さ 0.9 以上のものだけを残し、**原文の行そのもの**を画面の先頭に出す。一致しない行（作り話・題名だけの行・指示の言い直し）は捨てる。重複なし、4 行まで
3. その下に、いちばん近い資料の要点を原文のまま全部出す。AI の選び漏れがあっても見え、AI の準備中も先に読める
4. AI は検索結果が出たら自動で動く

## 検討した案
- AI の自由な要約を先頭に出す（最初の形）：意味のずれが一番目立つ場所に出る
- AI の要約はボタンで作るサブ機能にし、答えの本体は原文にする（2026-11-16 夜の形）：安全だが、LLM の役割が小さくなる。本人は「明らかにモデルの問題では」として、モデルを替えて先頭に戻すことにした
- 資料の行に番号を振って選ばせる（`docs/prompts/v2-numbered.json`）：番号ごと書く、指示文を答えに書くなど、かえって悪くなった
- 例を見せる（フューショット、`docs/prompts/v4-fewshot.json`・`v5-fewshot.json`）：選び方は変わるが一長一短。10 問すべてで良くなる版はなかった

## 結果
- 画面に出る AI の行は必ず原文なので、意味が変わることはない
- 大事な行を選び漏らすことがある（「雨で寒い」で「濡れた服」を落とすなど）。その下の原文で補う
- 関係の薄い資料から逆の行動を選ぶおそれがある（「足がつった」＝熱中症に、低体温症の「体を温め」）。→ 2026-11-18：0013 で、1 位から離れすぎた QA は AI に渡さないようにした（関連での絞り込みはしない）
