# 0011 マニュアルの書き方

> 2026-11-18：原本を `data/qa/*.md` の QA の形に移し、`data/manual/` は消した（0013）。「1 行に 1 つの要点」「仮データ」「題名の一括置換の警告」は QA でも引き継ぐ。行の順番は「大事な順」から「安全側を先に、やる順」に変えた（0012）。

- 状態：0013 で置き換え（2026-11-18）
- 日付：2026-11-16、2026-11-17

## 背景
- 検索・AI の選び出し・関連する資料・目次が、すべてマニュアルの構造に頼っている
- 文（。）で区切ると、「大声より体力を使わず、遠くまで届く」のように、前の文がないと意味が通らない断片ができた

## 決定
- `data/manual/*.md` に、`## 見出し` ごとに 1 項目を書く
- 見出しの次の行に `分類:`（目次のグループ）と `関連:`（関連する資料の題名）を書く
- 本文は **1 行に 1 つの要点**を、**大事な順に**書く。この行が検索・AI の選び出し・出典の単位になる
- 題名は名詞で書く（「現在地の確かめ方」「低体温症の予防」）。動詞の終止形で終わる題名は避ける
- 索引（`assets/rag/index.json`）は `npm run index` で作り直す。本文に別の項目の題名がそのまま入っていたら警告する

## 結果
- いまのマニュアルと用語集は、Claude が一般的な知識で書いた**仮データ（未監修）**。公開前に、信頼できる出典（山岳団体・警察・消防など）にもとづく内容に差し替える
- 題名を一括で置き換えたとき、本文の「すぐに救助を呼ぶ」まで「すぐに通報のしかた」に書き換えてしまう事故があった。上の警告はその再発防止
